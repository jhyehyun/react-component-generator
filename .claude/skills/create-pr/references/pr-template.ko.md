# PR 템플릿 (한국어)

작성 규칙:
- `<...>` 자리표시자는 모두 실제 내용으로 바꾼다. 남기지 않는다.
- 해당 없는 섹션은 지우지 말고 "없음"으로 적는다.
- 커밋 로그를 그대로 붙여넣지 말고 변경의 의미를 요약한다.

제목 형식: `<type>: <한국어 요약>` (feat / fix / refactor / chore, 70자 이내, 마침표 없음)

```markdown
## 개요

<이 PR이 무엇을 왜 바꾸는지 1~3문장>

## 변경 사항

- <변경 1>
- <변경 2>

## 변경 이유

<배경, 해결하려는 문제, 관련 이슈 (예: Closes #12)>

## 테스트

- [ ] `bun run test`
- [ ] `bun run lint`
- [ ] `bun run build`
- <수동 확인한 내용이 있으면 기재>

## 리뷰어 참고 사항

<중점적으로 볼 부분, 알려진 한계, 후속 작업. 없으면 "없음">
```
